# SecureLayer Wire Protocol & Contract Specification

## 1. Overview & Transport Protocol

SecureLayer supports two transport layers:
1. **HTTP/1.1 & HTTP/2 (REST/JSON Wire Protocol):** Used by Web Browsers, the Developer Dashboard, and edge HTTP Gateways.
2. **gRPC over HTTP/2 with Protocol Buffers v3:** Used for high-throughput, low-latency communication between distributed Gateways and the `security-core` Control Plane.

All production communications require **TLS 1.3** transport-layer security with forward secrecy (ECDHE key exchange).

---

## 2. HTTP Wire Headers Specification

Every request evaluated by SecureLayer uses standard and proprietary HTTP headers:

| Header Name | Required? | Type | Format / Example | Description |
| :--- | :--- | :--- | :--- | :--- |
| `Authorization` | Yes (for users) | String | `Bearer eyJhbGciOi...` | Standard OAuth 2.1 / OpenID Connect JSON Web Token. |
| `X-Message-Sha256` | Mandatory | String | `Base64(SHA-256(body))` | Base64-encoded cryptographic digest of the raw request payload body. Empty payloads hash the 0-byte string (`47DEQpj8...`). |
| `X-SecureLayer-Client-Id` | Mandatory | String | `banking-app` | Registered client application identifier. |
| `X-SecureLayer-Device-Id` | Mandatory | String | `dev-a-active-1001` | Unique hardware- or client-bound device identifier. |
| `X-SecureLayer-Client-Certificate` | Optional / Mode-dependent | String | Base64 or PEM string | Client X.509 device certificate used for application-layer mTLS verification. |
| `X-Transaction-Signature` | Optional (Required for transactions) | String | Base64 Ed25519 signature | Ed25519 digital signature over the business transaction payload to ensure non-repudiation. |
| `X-SecureLayer-Policy-Decision` | Injected by Gateway | String | `ALLOW` \| `DENY` | Enriched header passed downstream to upstream services indicating evaluation result. |
| `X-SecureLayer-Subject` | Injected by Gateway | String | `alice.developer@bank.example.com` | Verified subject claim extracted from JWT. |

## 3. Cryptographic Payloads: Wire Representation

### 3.1. AES-256-GCM Encrypted Envelope Format

When transmitting confidential payloads across boundaries, the encrypted envelope adheres to the following JSON structure:

```json
{
  "algorithm": "AES-256-GCM",
  "nonce": "iYowxjAtD+B1JfXf",
  "ciphertext": "Tf/h6o53hH9prQVscze5Rfgow6qffgJDTgPLw8bL...",
  "authTag": "ebBH27HXPFbtv8At2eLWyg==",
  "associatedData": "tenant:00000000-0000-0000-0000-000000000001",
  "keyVersion": "v1"
}
```

#### Field Specifications:
- `algorithm`: Must be `"AES-256-GCM"`.
- `nonce`: Base64-encoded 96-bit (12-byte) initialization vector generated using CSPRNG.
- `ciphertext`: Base64-encoded encrypted bytes.
- `authTag`: Base64-encoded 128-bit (16-byte) authentication tag generated by GHASH.
- `associatedData`: Optional plaintext string verified by the authentication tag.

        │                                                  │
        │ 1. POST /api/v1/devices/challenge-request        │
        ├─────────────────────────────────────────────────►│
        │    { "deviceIdentifier": "dev-a-1001" }          │

        │ 2. Return Random Challenge Nonce                 │
        │◄─────────────────────────────────────────────────┤

        │      "expiresAt": "2026-10-11T21:30:00Z" }       │
        │                                                  │
        │ 3. Sign Challenge with Local Private Key:        │
        │    signature = Sign(challenge, privKey)          │
        │                                                  │

        ├─────────────────────────────────────────────────►│
        │    {                                             │
        │      "deviceIdentifier": "dev-a-1001",           │
        │      "publicKeyPem": "-----BEGIN PUBLIC...",     │

        │                                                  │

## 4. gRPC Protocol Buffer Contracts

Core platform services are defined in `proto/securelayer/v1/`:

### `control_plane.proto`
```protobuf
syntax = "proto3";

package securelayer.v1;

option java_package = "com.securelayer.core.grpc";
option java_multiple_files = true;

service ControlPlaneService {
  rpc EvaluatePolicy (PolicyEvaluationRequest) returns (PolicyEvaluationResponse);
  rpc ValidateDeviceCertificate (ValidateCertRequest) returns (ValidateCertResponse);
  rpc RecordAuditEvent (RecordAuditRequest) returns (RecordAuditResponse);
}

message PolicyEvaluationRequest {
  string tenant_id = 1;
  string policy_name = 2;
  string subject = 3;
  string device_identifier = 4;
  string client_id = 5;
  string requested_resource = 6;
  string http_method = 7;
  repeated string user_roles = 8;
}

message PolicyEvaluationResponse {
  string decision = 1; // "ALLOW", "DENY", "REQUIRE_MFA"
  string reason = 2;
  string policy_name = 3;
  int32 policy_version = 4;
}

message ValidateCertRequest {
  string tenant_id = 1;
  string device_identifier = 2;
  string certificate_pem = 3;
}

message ValidateCertResponse {
  bool authenticated = 1;
  string device_id = 2;
  string device_state = 3; // "ACTIVE", "PENDING", "SUSPENDED", "REVOKED"
  string reason = 4;
}
```
